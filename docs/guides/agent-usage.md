# agent-usage — 如何与你的 Code Agent 协作

> 面向：人类成员（模块设计者）。
> 原则：Agent 的产出质量 ≈ 你给的上下文质量 × 你验收的严格程度。

## 1. 开工前：把上下文喂全

Agent 只知道你告诉它的。开工时至少给：

1. Issue 全文（方向、验收标准、范围边界）
2. 让它自己走阅读动线（从根 `AGENTS.md` 开始）——不要用你的口述替代文档
3. 你的模块设计文档路径（阶段二实现时）

反例：只说"帮我把错题本做了"——Agent 会用猜测填补所有空白。

## 2. 过程中：用规则说话，不用口味说话

- 让 Agent 遵守 iron-laws 与 git-workflow——它们是成文的，Agent 会百分之百执行
- 要求它先给计划再动手（先计划后实现，减少返工）
- 它停下来请示（Escalation）时：读它引用的条款，补信息或放宽范围；**不要教它绕过规则**——绕过一次，规程的权威就没了

## 3. 交付前：验收三查

1. **验收标准逐条对照**：Issue 里每一条都要有证据（命令输出、截图、测试结果）
2. **重实现测试**：设计文档与代码是否还一致（design-guide §5 分档）
3. **A 组自检表**：让 Agent 自己跑一遍机械项并附结果（design-guide §8），你抽查

## 4. 你和 Agent 的分工

- 设计决策（做什么、怎么划分）→ 你；实现决策（怎么写好）→ Agent
- Agent 发现设计有错 → 停下报告你（大档）；你改设计，它改代码——**不要让它顺手大改你的设计文档**
- Agent 的产出以你的名义进入仓库：PR 上的质量问题由你对外负责
