# 认证授权 对外契约（detail/api/认证授权.md）

status: active
所属域: 平台底座　维护者: 协调者侧　父文档: [../../design.md](../../design.md)

> 前缀 `auth`（登录态）与 `roles`（RBAC 管理）；约定见 [api-conventions](../../../../architecture/contracts/api-conventions.md)，路径省略 `/api/v1`。

## 1. 端点清单

| 方法与路径 | 语义 | 权限 |
|---|---|---|
| POST `/auth/login` | 登录：签发 accessToken(2h)+refreshToken(7d)，记登录日志 | 公开 |
| POST `/auth/tokens/refresh` | 刷新：refreshToken 换新双 token（滚动，旧 refresh 即时作废） | 公开（持有效 refresh） |
| POST `/auth/logout` | 登出：撤销当前 refresh（body：`{"refreshToken": "…"}`） | 登录即可 |
| PATCH `/auth/password` | 修改自己的密码（验旧设新），成功后撤销全部 refresh | 登录即可 |
| GET `/auth/me` | 当前账号画像：账号、角色集、权限码集、组织归属 | 登录即可 |
| GET/POST `/roles`；GET/PATCH/DELETE `/roles/{id}` | 角色管理（六预置角色只读，自定义角色可改） | `sys:role:read` / `sys:role:write` |
| POST `/roles/{id}/permissions` | 角色-权限授予（**全量替换**语义：body 为权限 ID 集合，空集合=清空） | `sys:role:write` |
| GET `/permissions` | 权限树查询（menu/button 两级树，code 全集） | `sys:role:read` |

> 实现对齐（2026-09-09）：单条 DELETE `/roles/{id}/permissions/{permissionId}` 并入全量替换接口；`/auth/me` 的 `orgId` 字段已预留、随组织架构模块接入后回填。

## 2. 关键约定

- **token 形态**：JWT；access claims = accountId、roleCodes、orgId、exp；refresh claims = accountId、jti（白名单键）。算法 HS256，密钥经配置注入不入库
- **权限校验**：接口层注解 `@RequirePermission("course:lesson:publish")`，无权限返回 `AUTH-003`；菜单/按钮可见性由前端按 `/auth/me` 权限码集渲染
- **登录失败**：用户名或密码错统一返回 `AUTH-001`（不区分暴露哪个错）；连续 5 次失败锁 15 分钟（`AUTH-002`）

## 3. 错误码（AUTH，一经发布语义冻结）

| 码 | 语义 |
|---|---|
| AUTH-001 | 用户名或密码错误 |
| AUTH-002 | 账号已锁定（失败次数超限） |
| AUTH-003 | 无权限访问 |
| AUTH-004 | 未登录或 token 无效/过期 |
| AUTH-005 | refresh token 无效或已撤销 |
| AUTH-006 | 预置角色不可修改 |
