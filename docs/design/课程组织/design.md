## 1. 这个模块解决什么问题

课程是「教」这条主链的起点：教师必须先有一门课程，才能往上挂章节课时、挂知识点、传课件、开班指派学员（[教师主流程 §七](../../product/K12教育系统.md)）。

而 K12 的课程不是一张自由表单——它天然带三个分类维度：**学段 × 学科 × 教材版本**。这个三维不是装饰，而是全系统的分类骨架：二期题库的题目标注维度必须与之对齐，否则学情分析无从谈起（[课程蓝图](../../product/blueprint/课程.md) 域导语）。

本模块交付两件事：

1. **三维分类模型**：三个维度各自由谁承载、哪些组合合法、谁来维护；
2. **课程档案**：教师按三维建课 → 改课 → 停用 的完整生命周期，以及各生命周期节点对下游的承诺。

验收标准逐条覆盖见 §5。

## 2. 边界

- **对外提供**：
  - 三维分类读契约——学段/学科走底座字典，教材版本与「学科-学段适用关系」由本域提供
  - 课程档案的读写契约（建/查/改/状态流转），前缀 `/api/v1/courses`
  - 课程与教材版本变更的领域事件（outbox 外发，Agent-ready 可观测义务）
- **依赖别人**：
  - 平台底座·系统管理：字典契约提供学段、学科两个维度的枚举值（[系统管理对外契约](../平台底座/detail/api/系统管理.md)）
  - 平台底座·文件服务：课程封面只存文件 ID，不存地址（[文件服务对外契约](../平台底座/detail/api/文件服务.md)）
  - 平台底座·工程规范：幂等 / 审计 / 事件外发三件套，接入方式见 [底座设计 §3.4](../平台底座/design.md)
- **明确不做**：
  - 章 / 节 / 课时结构（课程结构包）、知识点挂载（知识点树包 #8）、课件资源包（课件管理包）、开班与教学班（开班管理包）——各自独立任务包
  - 任何实现代码
  - 不拥有「教师-班级-课程任课关系」（归平台底座，[data-ownership](../../architecture/contracts/data-ownership.md)）——课程记录不含教师归属字段，只保留 `createdBy` 审计字段

## 3. 概要设计

### 3.1 三维分类模型与承载决策

| 维度 | 语义 | 承载方式 | 属主 | 理由 |
|---|---|---|---|---|
| 学段 | 小学 / 初中 / 高中 | 底座 sys 字典 `course_stage` | 平台底座 | 全系统共用枚举：招生入学测评、教务排课、学情按学段切分都要用；自建会让多域各存一份，违反 SSOT（[design-guide §4.7](../../guides/design-guide.md)） |
| 学科 | 语文 / 数学 / 物理 … | 底座 sys 字典 `course_subject` | 平台底座 | 同上——[系统管理契约](../平台底座/detail/api/系统管理.md) §2 已把「学段、科目」列为字典语义候选；学科本体是稳定枚举，无生命周期 |
| 教材版本 | 人教版高中数学（2019 修订） | 课程域实体 `textbook_edition` | 课程 | **不是稳定枚举**：带出版社、修订年份、适用学段/学科、启用停用生命周期；且二期题库标注要跨域消费 |

**决策要点**：字典承载「命名空间」（code → 展示名），域承载「适用规则与实体」。教材版本自建，因此必须登记 data-ownership（见 §3.7）。本域对字典只消费、不维护；字典项的增删由底座 `sys:dict:*` 权限管控。

### 3.2 合法组合约束

学段与学科不是自由笛卡尔积：小学不开物理，高中不开「品德与生活」。约束落在本域私有的 **`subject_stage_scope`（学科-学段适用关系）**：

- 一条 `subject_stage_scope` = 「某学科在某学段开设」
- 建课与改三维时必须命中一条 `enabled` 的关系，否则拒绝并返回 `CRS-002`
- 该关系是**域内私有数据**（只用于本域校验），按 [data-ownership](../../architecture/contracts/data-ownership.md) §规则 无需登记

**为什么不把适用关系塞进字典**：底座字典契约的项是扁平枚举，无法表达二元关系；把「物理适用于高中」编码成字典项名是拿命名空间当业务规则用。**为什么不并入教材版本实体**：学校可以先开「高中信息技术」课，教材版本稍后才登记——适用关系必须先于教材版本存在。

### 3.3 课程档案生命周期

```
        提交审核            审核通过
 DRAFT ──────────▶ PENDING_REVIEW ──────────▶ PUBLISHED
   ▲                     │                        │
   └──── 审核驳回 ────────┘                        │
                                                   ▼
 DRAFT / PENDING_REVIEW / PUBLISHED ──停用──▶ DISABLED（终态）
```

- `DRAFT`：建课即此态，三维可改，仅创建者与教务可见
- `PUBLISHED`：可被下游引用（开班、挂章节、编题标注）
- `DISABLED`：**终态，不可逆**——课程 ID 是主链共享引用键（任课关系、教学班、学习记录、成绩均按 `courseId` 引用），复活会让同一 ID 下历史语义与当前语义漂移，破坏学习记录与成绩的可追溯性。需要重新开课 = 新建课程（可基于原三维复制）

**三维锁定**：课程一旦 `PUBLISHED`，三维归属（学段/学科/教材版本）不可变更（`CRS-007`），仅描述性字段可改。理由：三维是题目标注与学情分析的对齐键，上架后改学科会让既有按学科聚合的数据与题目标注失真。`DRAFT`/`PENDING_REVIEW` 态改三维须重跑 §3.2 全部校验。

**审核上架归属**：总纲 §四角色矩阵中，课程域的「审核上架」是教务职责。本包把它实现为状态机的一环以形成最小闭环；若协调者判定审核应随「课件管理」包另立，本状态机可退化为 `DRAFT → PUBLISHED` 两态，**端点与错误码不变**（保留码位）。

### 3.4 停用约束（被下游引用时的行为）

停用是「**声明不再接受新建引用**」，不是「撤回已经发生的引用」：

| 方面 | 行为 |
|---|---|
| 既有下游引用 | 不受影响，继续可读可用——已建的章节课时、已挂的任课关系、已在读的教学班与已产生的学习记录一律不动（不级联） |
| 新建下游引用 | 必须被拒绝——拒绝点是**消费方各自的写路径**（校验课程 `status == PUBLISHED`），不是课程域 |
| 本域写路径 | 停用后本域所有写操作一律拒绝（`CRS-006`） |
| 数据保留 | 逻辑停用，**不物理删除**课程及其三维归属；本设计不提供 DELETE 端点 |
| 通知方式 | 停用触发 outbox 事件 `course.course.status-changed`，下游据此做业务处置（如教务端提示结班） |

**为什么本域不做「引用计数」门禁**：要判断「课程是否仍被在学教学班引用」，课程域就得反向依赖学习域与开班管理，与铁律 L7「域间依赖单向、依赖图无环（ArchUnit 在 CI 检查）」冲突。因此本域**只发事件、不反向查询**，把状态校验义务下推给消费方。

### 3.6 接缝问题（须协调者裁定，Agent 不自行裁定）

**问题**：[组织架构契约](../平台底座/detail/api/组织架构.md) 的错误码 `ORG-005`「引用的教师/**课程**/学年学期不存在或无效」意味着底座在建立任课关系时要校验课程有效性；而本域建课要消费底座字典（`sys:dict`）。若底座调用课程域校验课程，则出现 **底座 → 课程** 与 **课程 → 底座** 的双向依赖，构成 L7 禁止的环（ArchUnit 会直接构建失败）。

**建议裁定**（供参考，不作本设计前提）：底座侧 `courseId` 作**不透明引用**，只校验非空与格式；课程的存在性与状态由消费方在业务写路径把关。裁定落地时 `ORG-005` 中「课程」部分需修订 → 属契约变更，按 [design-guide §7](../../guides/design-guide.md) 须由协调者仲裁并写入契约。

**本设计的处理**：§3.4 的停用约束按「本域不反向依赖下游、消费方校验状态」撰写，与上述建议一致；若裁定结果相反，**仅 §3.4 的校验落点行需要改写，数据模型与端点不受影响**。

### 3.7 契约登记建议（Escalation 事项，本 PR 不修改契约）

本域自建 `textbook_edition`，且二期题库标注将跨域消费，按 Issue 要求须登记 [data-ownership](../../architecture/contracts/data-ownership.md)。该文件位于只读区（铁律 L3），修改须走 Escalation，故此处只给建议行：

```markdown
| 教材版本（学段×学科×出版社×版本名） | 课程域 | #7 课程组织设计新增；二期题库标注经契约接口消费 |
```

`courses` 前缀已存在于 [api-conventions §1](../../architecture/contracts/api-conventions.md) 资源前缀表（覆盖章/节/课时/课件/课堂记录），本包复用同一前缀，**无需新增前缀、无需契约变更**。错误码 `CRS-*` 为首次定义，一经合并即按 [api-conventions §4](../../architecture/contracts/api-conventions.md) 语义冻结、只增不改。
