# Agent 边界契约

status: v0.1-draft（2026-09-09 双运行时架构决策落档；冻结 v1 前为草案，变更须协调者裁定并在所有 open Issue 广播）

> 本文件定义业务运行时（Spring Boot 模块化单体）与 Agent 运行时（Python）之间的边界与交互契约。
> 分工总纲：**业务单体是「世界」**（数字学校本体，业务事实唯一属主）；**Agent 运行时是「操作者」**（大模型的运行与操作环境），观测和操作世界，但不拥有世界的数据。
> 实施次序：当前阶段只建业务单体，但须满足 Agent-ready（领域事件外发、契约 API 完备、写操作幂等、审计齐备）；Agent 运行时建设在系统生产稳定运行一段时间后启动（宪法 §1 建设次序；启动判据由蓝图定义、协调者裁定后生效）。

## 角色边界

| 职责 | 业务运行时（Spring Boot） | Agent 运行时（Python） |
|---|---|---|
| 业务事实存储与事务 | ✅ 唯一属主 | ❌ 禁止直连业务库 |
| 权限 / 审计 / 合规执行 | ✅ 确定性执行点 | ❌ 只能经契约 API 双身份调用 |
| 六端统一 API / BFF | ✅ | 流式输出经其转发 |
| 编排、工具循环、模型网关 | ❌ | ✅ |
| 记忆、RAG、向量存储 | ❌ | ✅（运行时自有库，可重建） |
| 建议产出（批改/评语/报告） | 受理确认与落库 | ✅ 产出 |

## 三种交互模式

1. **同步工具调用**（Agent → 业务）：Agent 的工具 = 业务契约 API 的受控封装；双身份传递（服务身份 + 末端用户身份）；写操作幂等
2. **领域事件**（业务 → Agent）：业务事件（作业提交、成绩发布、预警触发等）驱动主动型 Agent
3. **流式通道**（Agent → 前端）：Agent 输出经业务网关以 SSE/WebSocket 转发，前端不直连 Agent 运行时

## 建议与事实（human-in-the-loop）

- Agent 产出一律视为「建议」；高风险动作（成绩发布、缴费、面向家长/学生的定向触达）必须经人工确认门，由业务侧完成确认与落库
- 全部 Agent 写操作进审计：末端用户身份、Agent 标识、工具名、参数摘要
