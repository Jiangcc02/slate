# 蓝图：平台底座

status: draft

> 所有域共用的地基，**必须先行**（总纲 §十五：底座任务包最先完成，后续所有包依赖它）。详细模块见下方清单。

## 本域要什么（模块清单）

| 模块 | 优先级 | 依赖 | 状态 |
|---|---|---|---|
| 认证授权：登录态（JWT）、RBAC（学生/教师/班主任/教务/管理员/家长，到菜单/按钮级）、操作审计 | 一期 | 无 | 未开始 |
| 组织架构：机构 → 校区 → 学部（小/初/高）→ 年级 → 班级；教师归属与任课关系 | 一期 | 认证授权 | 未开始 |
| 用户中心：各类角色档案、批量导入、账号生命周期、家长-学生绑定（多对多） | 一期 | 组织架构 | 未开始 |
| 消息中心：站内信、公告、通知（邮件/短信/微信渠道预留） | 一期 | 用户中心 | 未开始 |
| 文件服务：视频/图片/课件的上传与存储（接 MinIO 或云 OSS） | 一期 | 无 | 未开始 |
| 系统管理：数据字典、参数配置、登录/操作日志 | 一期 | 无 | 未开始 |
| 工程规范：统一响应与异常、参数校验、接口文档（Knife4j）、ArchUnit 依赖检查、统一幂等、领域事件外发机制 | 一期 | 无 | 未开始 |
| 设备管理：教室白板设备的注册绑定、心跳监控、远程运维 | 四期 | [教室端专题](教室端.md) | 未开始 |

## 本域的成功画面

任一业务域开工时：登录态、权限、统一响应、异常、幂等、审计、事件外发全部现成可用，设计者只按契约实现业务。总纲 §二认知锚点：底座没建好，上面八个域全是危楼。

## 接缝与约束

- 数据属主（[data-ownership](../../architecture/contracts/data-ownership.md)）：账号与凭证、RBAC、组织架构与班级名单、任课关系、家长-学生绑定、消息投递、文件元数据、字典参数、教室设备
- 主链 ID 生成策略（雪花/自增）在底座设计定稿，全系统统一（[global-data-model](../../architecture/contracts/global-data-model.md)）
- JWT 过期与刷新、幂等 TTL 由底座设计定稿（[api-conventions](../../architecture/contracts/api-conventions.md)）
- Agent-ready 义务（铁律 L8）：底座提供机制（幂等、审计、事件外发），业务域接入
