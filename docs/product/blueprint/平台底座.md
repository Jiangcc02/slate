# 蓝图：平台底座

status: draft

> 所有域共用的地基，**必须先行**（总纲 §十五：底座任务包最先完成，后续所有包依赖它）。详细模块见下方清单。

## 本域要什么（模块清单）

| 模块 | 优先级 | 依赖 | 状态 |
|---|---|---|---|
| 认证授权：登录态（JWT）、RBAC（学生/教师/班主任/教务/管理员/家长，到菜单/按钮级）、操作审计 | 一期 | 无 | **已实现**（[detail/api/认证授权](../../design/平台底座/detail/api/认证授权.md)：双 token 登录/刷新/登出/改密/画像 + RBAC 管理 + 登录日志与失败锁定；家长角色随用户中心绑定落地） |
| 组织架构：机构 → 校区 → 学部（小/初/高）→ 年级 → 班级；教师归属与任课关系 | 一期 | 认证授权 | **已实现**（[detail/api/组织架构](../../design/平台底座/detail/api/组织架构.md)：五级树/名单入出班留痕/任课关系；名单变更外发领域事件） |
| 用户中心：各类角色档案、批量导入、账号生命周期、家长-学生绑定（多对多） | 一期 | 组织架构 | 已设计（[detail/api/用户中心](../../design/平台底座/detail/api/用户中心.md)） |
| 消息中心：站内信、公告、通知（邮件/短信/微信渠道预留） | 一期 | 用户中心 | 已设计（[detail/api/消息中心](../../design/平台底座/detail/api/消息中心.md)） |
| 文件服务：视频/图片/课件的上传与存储（接 MinIO 或云 OSS） | 一期 | 无 | 已设计（[detail/api/文件服务](../../design/平台底座/detail/api/文件服务.md)） |
| 系统管理：数据字典、参数配置、登录/操作日志 | 一期 | 无 | 已设计（[detail/api/系统管理](../../design/平台底座/detail/api/系统管理.md)） |
| 工程规范：统一响应与异常、参数校验、接口文档（Knife4j）、ArchUnit 依赖检查、统一幂等、领域事件外发机制 | 一期 | 无 | **已实现**（响应/异常/traceId/雪花 ID/ArchUnit+L1 CI 防线随骨架落地；幂等拦截器 Idempotency-Key 24h、操作审计 @Audited 切面落表、领域事件 outbox+轮询投递器随组织架构模块落地，2026-09-09） |
| 设备管理：教室白板等教学设备的注册绑定、心跳监控、远程运维、**报修工单**（报→派单→维修→验收；设施报修归校园服务域） | 四期 | [教室端专题](教室端.md) | 未开始 |

## 本域的成功画面

任一业务域开工时：登录态、权限、统一响应、异常、幂等、审计、事件外发全部现成可用，设计者只按契约实现业务。总纲 §二认知锚点：底座没建好，上面九个域全是危楼。

## 接缝与约束

- 数据属主（[data-ownership](../../architecture/contracts/data-ownership.md)）：账号与凭证、RBAC、组织架构与班级名单、任课关系、家长-学生绑定、消息投递、文件元数据、字典参数、教室设备
- 主链 ID 生成策略定稿（2026-09-09）：雪花 ID，全系统统一（[global-data-model §2](../../architecture/contracts/global-data-model.md)）
- JWT 过期与刷新、幂等 TTL 定稿（2026-09-09）：双 token 2h+7d、TTL 24h（[api-conventions §2/§6](../../architecture/contracts/api-conventions.md)）
- Agent-ready 义务（铁律 L8）：底座提供机制（幂等、审计、事件外发），业务域接入
- 一期设计成文（2026-09-09）：[docs/design/平台底座/](../../design/平台底座/)（概要 + detail/api 六模块 + detail/data）——底座实现任务包的需求依据
