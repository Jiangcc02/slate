# 蓝图：课程（教）

status: draft

> 教的载体。课程三维组织是 K12 特有的分类骨架，题库标注维度必须与之对齐，否则学情分析无从谈起。

## 本域要什么（模块清单）

| 模块 | 优先级 | 依赖 | 状态 |
|---|---|---|---|
| 课程组织：学段 × 学科 × 教材版本（人教版等）三维分类 | 一期 | 底座 | 已发包 #7 |
| 课程结构：课程 → 章 → 节 → 课时（视频/图文/课件） | 一期 | 课程组织 | 未开始 |
| 知识点树：挂章节（学情分析的命脉，行业对照"知识图谱管理"通常内嵌不独立） | 一期 | 课程结构 | 已发包 #8 |
| 课件管理（资源子层）：上传/导入、审核、共享、版本、引用；含"课时-资源包"与预缓存策略 | 一期 | 课程结构、底座文件服务 | 未开始 |
| 开班管理：课程实例化为教学班（讲师 + 学员名单 + 起止时间 + 学习计划） | 一期 | 课程结构、底座组织架构 | 未开始 |
| 课堂记录：板书等授课产物挂课时保存 | 四期（随教室端） | 课时-资源包 | 未开始 |

> 课件与题库互为"孪生兄弟"：同属教学资源层（一个挂课时、一个挂知识点），管理形态高度相似——可设计成一套通用资源管理骨架，课件和题目是其上的实例（总纲 §九）。

## 本域的成功画面

教师主流程前半段（总纲 §七）：按三维建课、挂知识点、传课件、开班指派学员——开班完成的那一刻，学习中心立刻可用；教室端"课件在课时上，不在 U 盘里"（[教室端专题](教室端.md)）。

Agent 建设期增量（总纲 §三）：教师向 Agent 描述知识点理解 → 生成交互式课件（pptx / 交互 HTML / 富文本）与分层练习 → **教师审定后挂课时**（主线确认门，宪法 §1）。

## 接缝与约束

- 数据属主：课程/章/节/课时、知识点树、课件资源、课堂记录（[data-ownership](../../architecture/contracts/data-ownership.md)）
- 他域只存课程/课时/知识点 ID，不复制业务字段（[global-data-model](../../architecture/contracts/global-data-model.md)）
- 内容合规红线：课件审核后才可上架（总纲 §十二）
- 教务「审核上架」角色消费本域接口（总纲 §四矩阵）
