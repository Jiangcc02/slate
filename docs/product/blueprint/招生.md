# 蓝图：招生

status: draft

> 机构的命脉；公立形态裁剪为报名录取（宪法 §1 明确不做校外培训形态，公立/私立差异由本域裁剪）。排期：**四期按定位选配**（首年部署用底座批量导入建班，招生域随私立定位启用）。

## 本域要什么（模块清单）

| 模块 | 优先级 | 依赖 | 状态 |
|---|---|---|---|
| 招生线索与渠道管理 | 四期（按定位） | 底座 | 未开始 |
| 报名 | 四期（按定位） | 线索/渠道 | 未开始 |
| 入学测评（复用测评域，跨域契约调用） | 四期（按定位） | 测评域 | 未开始 |
| 录取 | 四期（按定位） | 报名、入学测评 | 未开始 |
| 分班（分班动作写底座组织架构的班级名单） | 四期（按定位） | 录取、底座组织架构 | 未开始 |

## 本域的成功画面

管理者主流程的起点（总纲 §七）：线索 → 报名 → 测评 → 录取 → 分班闭环跑通；孩子分进班级后，学籍（教务）、家长绑定（底座）随入学建立——招生-交付-口碑闭环（总纲 §八-5）的入口。

## 接缝与约束

- 入学测评复用测评域：经契约接口调用，不复制题目数据
- 录取产物分流：班级名单归底座、学籍归教务、家长-学生绑定归底座用户中心（[data-ownership](../../architecture/contracts/data-ownership.md)）
- 公立裁剪：砍掉线索/渠道运营，保留报名 → 录取
