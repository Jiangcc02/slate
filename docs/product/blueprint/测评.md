# 蓝图：测评（练测）

status: draft

> 练与测的载体，二期能考试的主力域。行业对照：组卷、在线考试、成绩分析（网上阅卷属重系统不自建，宪法 §1）。

## 本域要什么（模块清单）

| 模块 | 优先级 | 依赖 | 状态 |
|---|---|---|---|
| 题库：五种题型（单选/多选/判断/填空/简答）、按知识点/难度归类、Excel 批量导入 | 二期 | 课程域知识点树 | 未开始 |
| 组卷：手动选题 + 随机抽题（按题型/难度/知识点，可每人卷面不同） | 二期 | 题库 | 未开始 |
| 三形态·作业（不计时）：答题流载体（任务流在学习域） | 二期 | 组卷、学习域任务流 | 未开始 |
| 三形态·测验（随堂实时，含教室端推送） | 二期（教室端场景四期） | 组卷、WebSocket 通道 | 未开始 |
| 三形态·考试（正式：防作弊 + 断线续答 + 自动交卷） | 二期 | 组卷 | 未开始 |
| 判分：客观题自动、主观题教师批阅、复核 | 二期 | 答题记录 | 未开始 |
| 成绩：发布、年级/班级排名、历次纵向追踪 | 二期 | 判分 | 未开始 |
| 错题本、自主刷题 | 二期 | 成绩、答题记录 | 未开始 |
| 试卷分析：难度/区分度统计 → 题库优化 | 二期（持续运营） | 成绩 | 未开始 |

## 本域的成功画面

考试主流程（总纲 §七）：命题入库 → 组卷 → 发布 → 答题（乱序/倒计时/防切屏）→ 交卷（幂等/自动交卷兜底）→ 判分 → 发布 → 试卷分析。试题质量闭环（总纲 §八-3）让题库越用越准；错题本支撑学生成长闭环（§八-2）。

## 接缝与约束

- **生产级技术要点**（总纲 §五）：考试状态机（Redis 会话）、交卷幂等、批量判分异步化、延迟任务自动交卷、防切屏留痕
- 作业答题流归本域（仲裁见 [data-ownership](../../architecture/contracts/data-ownership.md)）；入学测评被招生域复用（契约调用）
- 成绩是学情域画像的源数据：源数据归源域，学情只经契约消费
- 题库标注维度必须对齐课程域三维组织（学段 × 学科 × 教材版本）
- 网上阅卷（扫描硬件耦合）不自建——重系统红线
