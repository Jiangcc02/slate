# 蓝图：教室端（白板）专题

status: draft

> 触点层第 5 个入口（总纲 §二/§三），**不是独立域**，而是横跨课程（课件运行时/课堂记录）、教务（课表五要素）、测评（随堂测验）、底座（设备管理）的跨域交付切片。四期交付，最早三期可启动 MVP：扫码登录 + 课表定位 + 课件调用（总纲 §十四）。

## 本专题要什么（功能模块）

| 模块 | 依赖 | 状态 |
|---|---|---|
| 身份与登录：扫码免密登录（教师手机端扫白板二维码）、超时自动登出、下节课教师无缝交接 | 底座认证授权 | 未开始 |
| 课表感知：按 教室 + 当前时间 自动定位当节课；显示今日本教室课表 | 教务课表五要素 | 未开始 |
| 课件运行时：拉取"课时-资源包"，视频流式播放不整包下载 | 课程域课件资源 | 未开始 |
| 电子白板：多点书写、多页板书、板书保存为课堂记录挂到课时 | 课程域课堂记录 | 未开始 |
| 课堂工具：随机点名、抢答、计时器、聚光灯、学科工具（几何/函数图像） | 学习域课堂互动参与 | 未开始 |
| 随堂测验：题目推送、实时收回（WebSocket）、当场统计展示——测评域"测验"形态的课堂实时版 | 测评域、WebSocket 通道 | 未开始 |
| 弱网兜底：当天课件本地预缓存，断网也能上课 | 课件运行时 | 未开始 |

## 成功画面

总纲 §七课堂时间线：上课前白板按课表自动唤醒 → 扫码登录 → "课件在课时上，不在 U 盘里" → 授课互动 → 板书保存为课堂记录（学生端可回看）→ 下课自动登出。教学质量闭环的数据起点从课后提前到课中（总纲 §八-1）。

## 涟漪与约束

**对已有模块的涟漪**：
1. 课件管理系统：新增"课时-资源包"概念与预缓存策略
2. 排课模型：教室成为一等公民，建教室-班级常驻绑定
3. 测评域：随堂测验成为第三个消费场景，需 WebSocket 实时通道
4. 合规：课堂实录录课涉及学生肖像声音，监护人同意 + 严格权限——红线项，一期不做

**技术现实约束**：
- 教室大屏（希沃/鸿合/MAXHUB）主流 Android，部分带 Windows OPS 模块
- 最现实路径：**Web 版教室端**（Vue 3 大屏适配）跑在大屏浏览器或 OPS Chrome 里，复用全栈技术栈；板书用 Canvas 成熟手写库
- 交互规范：触摸优先（大按钮）、无 hover、无键盘（登录全靠扫码）、16:9 横屏常亮

**Code Agent 交付切分**：① 后端支撑（资源包 API、扫码登录、课堂记录、随堂测 WebSocket 通道）② Web 教室端（依赖①契约）③ 设备管理（心跳/远程指令）。电子白板书写体验（手写延迟、笔迹平滑）是 Agent 交付质量洼地，必须用成熟库。
