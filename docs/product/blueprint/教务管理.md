# 蓝图：教务管理（管）

status: draft

> 学校运营后台。排期说明：一期「能上课」仅依赖底座班级与开班名单；教务本体（课表/排课/考务/学籍）**三期建齐**（总纲 §十四，课表是四期教室端的前置），教师工作量四期。

## 本域要什么（模块清单）

| 模块 | 优先级 | 依赖 | 状态 |
|---|---|---|---|
| 校历与课表：课表五要素（时间 + 班级 + 课程 + 教师 + 教室）；教室为一等实体，教室-班级常驻绑定 | 三期（教室端四期前必须就绪） | 底座任课关系、课程域 | 未开始 |
| 排课：冲突检测；走班选科（新高考）待决 | 三期 | 课表 | 未开始 |
| 考务编排 | 三期 | 课表、测评域 | 未开始 |
| 学籍管理：在校状态、转班/休学/结业异动 | 三期 | 底座班级名单 | 未开始 |
| 教师工作量 | 四期 | 底座任课关系 | 未开始 |
| 全校数据总览（校长端） | 三期 | 学情域 | 未开始 |

## 本域的成功画面

管理者主流程（总纲 §七）：导入学员 → 分班排课 → 过程监控 → 结业报表 → 数据决策。[教室端专题](教室端.md)课堂时间线的第一步"按课表时段自动唤醒"就建立在本域课表五要素上。

## 接缝与约束

- 课表五要素与 ID 引用规则 SSOT 在 [global-data-model](../../architecture/contracts/global-data-model.md)；教室（空间）实体属主在本域，教室内的设备实体属底座
- 转班场景是模块化单体决策的招牌反例（总纲 §十）：一个事务改一条记录，全模块瞬间一致
- 排课属约束求解算法（重系统例外，总纲 §九），设计期单独评估
